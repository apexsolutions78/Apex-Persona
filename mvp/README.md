# Apex Persona MVP API

This is the internal API for the first four learning layers: governed persona seeds, research planning, ingestion, atomization, evidence validation, and retrieval. It does not build a public chatbot or synthesize persona identity yet.

## Run locally

Use Node.js 20 or newer and MySQL 8.0.16 or newer (or a compatible DirectAdmin MySQL service). Copy `.env.example` to `.env`, fill in a database/user created for this application, then run:

```text
npm ci
npm run db:setup
npm run dev
```

The setup command only initializes an empty database and records schema version `001_core`. It refuses to install over an untracked schema. Configure `PORT` with the port provided by DirectAdmin/Passenger; the server listens on that port.

## Milestone 1 API

- `GET /health` — checks the API and database connection.
- `POST /api/v1/personas` — create a persona seed. Required fields: `name`, `learning_goal`, and bounded `scope` with at least one included or excluded topic.
- `GET /api/v1/personas?limit=50&offset=0` — list persona seeds.
- `GET /api/v1/personas/:personaId` — read a persona seed.
- `POST /api/v1/personas/:personaId/learning-runs` — create an auditable learning run and generate 10–30 planned queries across definitions, official sources, research, procedures, cases, failure modes, critiques, and current updates.
- `GET /api/v1/personas/:personaId/learning-runs` and `GET /api/v1/learning-runs/:runId` — inspect a run and its query plan.
- `PATCH /api/v1/learning-runs/:runId/query-plan` — approve or reject selected planned query IDs.
- `PATCH /api/v1/learning-runs/:runId/status` — change the run lifecycle status.

Request bodies and errors are JSON. UUIDs are generated by the Node application. Configuration and secrets come from environment variables; never commit `.env`.

## Storage choices

MySQL stores workflow, source provenance, version history, evidence, validation scores, review tasks, concepts, and retrieval logs. Raw files and normalized content use local storage during development, with `raw_object_uri` and `normalized_text_uri` fields designed to support object storage later. MySQL full-text indexes provide the initial text search; the embedding registry and concept tables leave room for vector search and graph traversal without requiring those services on day one.

The extractor and validator must keep evidence separate from claims. A knowledge atom cannot be treated as trusted because one model agrees with it. Default retrieval will filter by stored confidence and preserve conflicts. All scoring components and algorithm versions are stored for explanation and reprocessing.
